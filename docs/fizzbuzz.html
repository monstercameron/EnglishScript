FizzBuzz, Every Way

One small program in EnglishScript, and the same program in 31 of its rivals: the English-like languages since 1955, and the new ones that ask a model.

FizzBuzz counts from 1 to 100, saying “Fizz” for a multiple of three, “Buzz” for a multiple of five, “FizzBuzz” for both, and otherwise the number. It is small enough to show whole, and it needs a loop, a choice and a little arithmetic, which is where English-like languages differ most.

Each sample was written for this page from its language's own documentation, and is marked with how far it was checked: run, when it was run and printed FizzBuzz exactly (3 of them); checked, when every construct was checked against the documentation but nothing here could run it; partly checked; or not a program, for a specification, or for a request that hands the arithmetic to a model. Some of these languages cannot do it at all, and their cards say why. The opposition tells each one's story.

SQL 1974

English-like languagesRun13 lines

WITH RECURSIVE numbers(n) AS (
    SELECT 1
    UNION ALL
    SELECT n + 1 FROM numbers WHERE n < 100
)
SELECT CASE
           WHEN n % 15 = 0 THEN 'FizzBuzz'
           WHEN n % 3 = 0 THEN 'Fizz'
           WHEN n % 5 = 0 THEN 'Buzz'
           ELSE CAST(n AS TEXT)
       END AS result
FROM numbers
ORDER BY n;

Written in SQLite's dialect: a recursive common table expression makes the numbers 1 to 100, and CASE picks the word. The % operator works in SQLite, PostgreSQL and MySQL; standard SQL spells it MOD(n, 15).

Computes it by itself. Run with sqlite3 3.49.1 (Python's sqlite3); output matched FizzBuzz exactly.

Natural 1979

English-like languagesChecked21 lines

DEFINE DATA LOCAL
1 #N  (I2)
1 #Q  (I2)
1 #R3 (I2)
1 #R5 (I2)
END-DEFINE
*
FOR #N 1 TO 100
  DIVIDE 3 INTO #N GIVING #Q REMAINDER #R3
  DIVIDE 5 INTO #N GIVING #Q REMAINDER #R5
  DECIDE FOR FIRST CONDITION
    WHEN #R3 = 0 AND #R5 = 0
      WRITE NOTITLE 'FizzBuzz'
    WHEN #R3 = 0
      WRITE 'Fizz'
    WHEN #R5 = 0
      WRITE 'Buzz'
    WHEN NONE
      WRITE #N
  END-DECIDE
END-FOR
*
END

Natural has a DIVIDE statement that gives a remainder, so each number is divided twice before a DECIDE chooses the word. NOTITLE, written once, stops Natural adding its usual page title to the whole report, and numbers are written right-aligned in their field, as in any Natural report.

Computes it by itself. Structured mode. DEFINE DATA, FOR, DIVIDE ... GIVING ... REMAINDER, DECIDE FOR FIRST CONDITION and WRITE NOTITLE checked against the Natural 8.2.7 statements reference (read from the Internet Archive's copies; the live pages now return 404). Osmosian Plain English 2006

English-like languagesPartly checked12 lines

To run:
  Start up.
  Loop.
  If a counter is past 100, break.
  If the counter is evenly divisible by 15, write "FizzBuzz"; repeat.
  If the counter is evenly divisible by 3, write "Fizz"; repeat.
  If the counter is evenly divisible by 5, write "Buzz"; repeat.
  Convert the counter to a string.
  Write the string.
  Repeat.
  Wait for the escape key.
  Shut down.

"If a counter is past 100" both adds one to a new local counter and tests it, so the loop needs no separate counting step. Every conditional fits on one line, as the language requires.

PENG 2002

Controlled EnglishPartly checked1 lines

No sample is given. PENG's published papers show conditionals, universal quantifiers, negation and comparatives over user-defined words, but no arithmetic, no remainder and no output, so a FizzBuzz written in PENG would be invented rather than checked.

                    instructions="Which word does this number get in FizzBuzz",

                        "Fizz": "A multiple of 3 but not of 5",
                        "Buzz": "A multiple of 5 but not of 3",

        )
        word = response.choices["word"].choice
        print(n if word == "number" else word)

Jev writes no text and does no arithmetic: it gives a probability to each of four listed answers, so this sends a hundred requests to guess what one line of remainder arithmetic would compute exactly. It is the wrong tool for FizzBuzz, and its documentation says to keep questions simple and do the rest in code.
