System 0, 1 and 2

The program's own sentences, a model that judges, and a model that writes: which work belongs to which, from a single rule to a cascade through all three.

A program that uses a language model has to decide which of its work is the model's. This page sorts that work into three systems, and shows, from the simplest case to a cascade through all three, how an EnglishScript program uses each.

Three systems

Daniel Kahneman's Thinking, Fast and Slow describes two ways of thinking: System 1, fast and intuitive, and System 2, slow and deliberate. In September 2026 TypeSafe AI named a class of model after the first: a System One model, such as their Jev, which writes no text and answers closed questions with how likely each answer is. Language models that write, and that can reason at length, stand where System 2 does.

Below both there is a third layer, which this page calls System 0. The name is this project's, not TypeSafe's or Kahneman's. System 0 is the program itself: sentences that are read one way, carried out exactly, and the same on every computer. It does not judge and it does not guess. Everything that can be stated as a rule belongs there.

The design follows from one rule: the decision is always System 0's. A model may judge, and may write, but what happens next is decided by sentences that anyone can read. TypeSafe's own guide to building with a System One model says the same in other words: keep the control flow, the rules and every action in ordinary code, and use the model only for the judgements code cannot make.

From simple to complex

Each example below was compiled and run when this page was built. Where a model would answer, answers written by hand stood in for it, and they are shown beside the program, so what it printed is real. “Open in the playground” runs an example in your browser. There is no model in a browser, so there you answer as the model, and see each question as the model would.

1. Only System 0 System 0

A refund that the rules can decide is decided by the rules. Nothing here is a matter of judgement, so no model is asked, and the answer is the same every time and on every computer.

No model was asked.

Most of a program should look like this. The cheapest, fastest and most trustworthy decision is the one that needs no model at all.

2. One question to System 1 System 1

Whether a customer is asking for a refund is a judgement about words, so it goes to the judge. The judge answers how likely it is, and the program decides what to do in three bands: act when the judge is sure, hold for a person when it is not, and leave it alone when it is unlikely.

Answers given by hand, standing in for a model:

  • The judge: 94%

The thresholds are in the program, where anyone can read them and change them. TypeSafe's documentation suggests 70% and 30% as a place to start for a yes-or-no question, to be tuned on real data.

3. A verdict from a set of choices System 1

When the answer is one of several, the choices are a set the program defines, and each may be given a meaning for the judge. The verdict is the likeliest choice, and its likelihood says how sure the judge is of it.

Answers given by hand, standing in for a model:

  • The judge: returns 5%, billing 81%, shipping 14%

The judge is told about the letter as a whole: its kind, its name and each of its properties, one to a line. It cannot answer with a team that is not in the set: such an answer is a problem, not a fourth team.

4. A grade on a scale System 1

When the choices are in order, low to high, the answer can be a grade. A verdict picks the likeliest choice. A grade is worked out from every chance at once, as TypeSafe's Score is: the choices are numbered in order, the chances weight the numbers, and the grade is the choice nearest the result. On a judge that cannot make up its mind between the ends, the two differ.

Answers given by hand, standing in for a model:

  • The judge: low 45%, middle 10%, high 45%
  • The judge: low 45%, middle 10%, high 45%

The judge split between low and high. The verdict takes the first of the two likeliest, low; the grade takes the middle of the scale, which is what a split between the ends means. Which to ask for is the program's choice, and it is written in the sentence.

5. Small questions, combined in System 0 System 0 and 1

A broad question hides several judgements in one answer. TypeSafe's guide calls asking narrow questions the most important thing to get right. Here three narrow questions about a message are combined by the program into a measure of risk, with weights the program chooses.

Answers given by hand, standing in for a model:

  • The judge: 97%
  • The judge: 91%
  • The judge: 62%

The weights are ordinary numbers in an ordinary sentence. Changing how much a promised prize counts is an edit to the program, not to a prompt. Three judgements in a row about the same message can be put to the judge together, as Jev is meant to be asked.

6. A question to System 2 System 2

Some work is writing, not deciding: a summary, a figure read out of a sentence. That goes to a model that writes. Its reply is read by the same strict reader as a person's typed reply, so a figure written in words is not quietly taken for a number.

Answers given by hand, standing in for a model:

  • The model: “A refund for a vase that arrived broken.”
  • The model: “forty dollars”
  • The model: “$40”

The second question was answered first with “forty dollars”, which cannot be read as money. The model was told why, and asked again, and its second answer was used. A third failure would have been a problem the program could catch.

7. A cascade: System 0, then 1, then 2, then a person All three

Each layer does only what it is for. The rules come first and settle what they can. The judge is asked only about what is left. When the judge is unsure, a model that reasons is asked for a second opinion, and when the two disagree, a person decides.

Answers given by hand, standing in for a model:

  • The judge: returns 5%, billing 48%, shipping 47%
  • The model: “billing”

The letter is about a charge for something that never came, so the judge split between billing and shipping. The second opinion said billing. Because both agreed, the letter went to billing; had they differed, it would have waited for a person. The order of the layers is the order of their cost.

8. Questions given names System 1 and 2

A question asked in several places can be given a name, as a worked-out value whose whole body is one question. It is then used like any other value. Because it asks a model, it may be used only where asking is allowed: never inside a rule or an adjective, so nothing the language checks by itself can ever ask a model.

Answers given by hand, standing in for a model:

  • The judge: returns 93%, billing 4%, shipping 3%
  • The judge: returns 2%, billing 3%, shipping 95%
  • The model: “A refund for a cracked kettle.”
  • The model: “To know where a late parcel is.”

In a run, the same question about the same thing is asked once and answered once, so a sentence still means one thing however often it is used.

9. When nothing is listening System 0

A program that asks a model must still run when no model is there: on a laptop with no key, in a test, in an outage. That is a problem like any other, and a program can catch it and fall back on what it can do alone.

Nothing was connected.

This one was run with nothing connected, as the page was built. A judge that answered with something unusable, such as a team not in the set or a chance above 100%, would be the second kind of problem, “a bad reply”.

Testing a program that asks a model

A program whose answers come from a model is only as repeatable as the model. Three things make it testable all the same.

  • Record and replay. Run it once with a model and keep what was said: --model record:answers.txt:anthropic. Replay it as often as you like with no model at all: --model replay:answers.txt. examples/triage.english comes with answers to replay.
  • One answer per question. In a run, the same question about the same thing is asked once, so two sentences cannot be given two different answers to one question.
  • The examples run alone. --test runs a program's For example sentences with nothing connected, so a test never depends on a model being there, and a program with a fallback goes on.

Connecting a model

The compiler never loads a model. Whoever runs a program chooses who answers:

python -m englishscript program.english --model person          you answer, as the model would
python -m englishscript program.english --model anthropic       a Claude model writes and judges
python -m englishscript program.english --model jev             TypeSafe's Jev judges
python -m englishscript program.english --model jev+anthropic   Jev judges, Claude writes
python -m englishscript program.english --model jev+openai:gpt-6-luna   Jev judges, GPT-6 Luna writes
python -m englishscript program.english --model replay:answers.txt

Jev supplies judgments. Used alone, it raises “no model” for a writing request. The maintenance desk combines Jev with GPT-6 Luna for written handoffs and second opinions. Both connections have been checked against their live services with the six-ticket sample and with an image question. Automated tests also check the OpenAI and Anthropic request and reply formats. Claude can estimate probabilities.

What to be careful of

  • A probability is not a promise. TypeSafe's documentation says that its confidence describes how concentrated an answer is, not the chance that it is right, and that calibration holds over many answers, not one. Choose thresholds by trying them on real cases.
  • Speed and price are the vendor's figures. Jev's claims of answers in a tenth of a second, at a fraction of a language model's cost, come from TypeSafe's own measurements.
  • A model can be misled. A judgement about a customer's message is a judgement about text the customer wrote. Keep what a judgement can make happen small, and keep a person in the loop where the cost of being wrong is high.
