# EnglishScript benchmark plan · The Boulder Badge

**Review draft · 20 November 2026**  
**EnglishScript baseline** · `acf28a2` on `main`  
**Game reference** · English Pokémon Red (USA/Europe) on the original monochrome Game Boy (DMG)  
**Playable finish** · Complete the opening of Pokémon Red and earn the Boulder Badge with any of the three starters.

The default game must reproduce the original opening through Brock. A player following the same inputs should see the same pixels, on the same game frames, and reach the same game state. EnglishScript must produce those results. The language benchmark also lets a reviewer pick a feature, open the chapter that uses it, and replay its effect.

## Playable campaign

The [campaign](../../docs/red/index.html) runs from the opening to the post-Brock reward dialogue. The controller fixtures choose each starter, deliver Oak’s parcel, receive the Pokédex, fight Geodude and Onix, and check the badge, TM34 and prize money. Speaking to Brock again leaves those rewards unchanged. [Campaign tests](../../tests/test_red_campaign.py)

The [frame comparator](../../tools/compare_red_frames.py) also runs the original English Red and checks four-shade frames. The same timed input trace diverges at naming. Independently aligning the initial bedroom at (3, 6), facing north, leaves 2,748 differing pixels out of 23,040. The selected title frames differ at 6,371 pixels. Exact parity is still open.

## Calibration room

The [Field Lab](../../docs/boulder/index.html) draws a 160×144 canvas and accepts movement while a direct top-level model question awaits a recorded reply. The [replay test](../../tests/test_boulder.py) compares runs on the same input. The [browser check](../../tools/check_boulder_browser.cjs) reads the actual canvas before and after movement and restart. It takes an Edge executable path and a temporary directory as arguments.

## What “pixel for pixel and gameplay match” means

| Contract | Acceptance check |
|---|---|
| One reference | Use English Pokémon Red (USA/Europe), cartridge SHA-1 `ea9bcae617fdf159b045185467ae58b2e4a48b9a`. Pin a reference emulator build, DMG hardware profile, boot state, divider/timer phase, save contents and settings. Begin at cartridge entry after the hardware boot ROM, with an empty save for the new-game runs. Include the opening animation, title screen, menus, naming and Oak’s introduction. End when the original post-Brock reward sequence returns control to the player. |
| Every pixel, every game frame | The page library owns a native HTML `<canvas width="160" height="144">` for the game screen. Compare the final **160×144 array of four DMG shade indices** on every reference frame before display scaling. Every one of the 23,040 positions must agree. Compare frame counts and ordering as well. A late text glyph, one wrong sprite pixel, or a transition that finishes a frame early fails. Keep the first differing frame, coordinates, expected and actual values, and a diff image. No tolerance, masks, skipped transitions or frame realignment. |
| Same inputs, same game | Drive the cartridge and EnglishScript from the same initial conditions with timestamped Game Boy button presses, releases, holds and idle intervals. Compare the map, tile and facing, NPC position, script and menu state, party order, stats, HP, PP, status, experience, money, inventory, Pokédex, quest flags and battle decisions as applicable. Check when events happen as well as their results. Compare save/reload behavior using the same subsequent inputs. |
| Actual game timing and chance | Advance the simulation at the DMG clock, approximately **59.73 game frames per second**. Present through a separate browser display clock. Reproduce the cartridge’s divider-dependent random updates, consumption order, move selection, arithmetic and rounding. Random draws captured from the cartridge are diagnostic evidence. A full replay must generate its own draws from the matched starting state. |
| Procedural graphics and sound | All visible graphics, including lettering, come from EnglishScript drawing procedures. Match the reference shapes and poses using the allowed primitives. Prohibit imported sprites, per-pixel lookup grids, per-frame playback and disguised bitmap payloads. Recreate the cartridge’s music, effects, cries and cue timing programmatically. Reference captures are test expectations. The playable build must run independently of the cartridge, emulator and captures. |
| Extensions coexist | Ordinary directions, A, B, Start and Select retain their cartridge behavior. A separate companion control opens free conversation with the selected person or launches the Field Lab. Its text and controls live outside the game viewport. Running a model can produce observations or choose player inputs. The cartridge’s NPC dialogue, opponent AI and quest scripts remain authoritative inside the faithful game. |

The reference build is identifiable by its published cartridge digest. The DMG has its own frame cadence, and Red’s randomness reads the hardware divider. These facts determine how the comparison harness must be built. [Cartridge digest](https://github.com/pret/pokered/blob/master/README.md) · [DMG rendering timing](https://github.com/gbdev/pandocs/blob/master/src/Rendering.md) · [Red’s random routine](https://github.com/pret/pokered/blob/master/engine/math/random.asm)

**First feasibility test.** Implement the title logo and its transition, the player’s bedroom including one step and one text box, and one Brock battle animation as small independent fixtures. Draw from procedures and compare every frame. This deliberately tests lettering, irregular silhouettes, scrolling, sprite priority and battle poses before authoring the whole route. If a fixture cannot meet zero differences under the no-bitmap rule, record the failing pixels and procedure as an open blocker. Passing video playback cannot satisfy this test.

**Coverage of the match.** Keep a manifest of every in-scope map, reachable room, NPC appearance, dialogue branch, encounter, menu and battle mechanic. Maintain three complete new-game-to-badge input recordings, one per starter, plus short branch recordings for losses, retries, held or mistimed buttons, text speed and battle options, bag limits, saving and continuing, and optional trainers. Add generated input sequences from known checkpoints. Report exactly which combinations have passed and which remain untested. A successful walkthrough alone cannot establish parity across every possible input.

## 1. What counts as complete

The [syntax exercise checklist](EnglishScript%20-%20Syntax%20exercise%20checklist.md) enumerates 407 structural checks from all 61 grammar productions, plus lexical, runtime and integration cases. Its [Boulder Badge Field Lab](Boulder%20Badge%20Field%20Lab.english) is already runnable against the baseline compiler. Its 92 passing assertions provide an independent starting point for the game.

**Build the standard library as part of the benchmark.** The [standard library and diagnostics plan](EnglishScript%20-%20Standard%20library%20and%20diagnostics.md) defines which game needs become reusable operations, which failures an English program can handle, and how authors and players see them. Its first two regressions come from the shipped compiler and playground. Every new public operation needs an ordinary English example outside the game and evidence for its success, failure and cleanup behavior.

- **Every documented form gets a row.** Start with the 61 named productions in §11. Split their alternatives, meaningful optional forms, operators, literals and word spellings into individually checkable entries. Add semantics that live only in prose, including rollback, optional-value narrowing, stable iteration, and model caching. Add the proposals in §§12–13 and a design row for each open item in §14.
- **Every accepted form earns its coverage in executable EnglishScript.** Assign it to a reachable story beat, conversation, battle, menu, or the companion’s playable Pokédex tools and Oak’s Field Lab. Run the published game entry point and check an observable result. Compile-only definitions such as private exports and library declarations get a consumer, a visibility or type check, and a runtime effect where applicable. The lab lets the player inspect a battle, edit a copy of a team, or compare replays. A lab experiment owns its own save.
- **Refusals have their own evidence.** A broken example runs in the compiler harness and asserts the diagnostic and source location. Keep the game runnable. Assertions in Python can check results. Game mechanics, character decisions and drawing instructions must be visible in the EnglishScript source.
- **A gap becomes compiler work.** Capture the failing English sentence first. Specify the meaning and ambiguity rules, implement it through the normal compiler and runtime entry points, exercise it in the game, then publish the reference and editor updates. A Python helper that computes an entire move or chooses a quest outcome earns no language coverage.
- **Publish the denominator.** Each release reports accepted forms exercised, required refusals verified, designed features still missing, and open designs awaiting a decision. An open row keeps the full-language milestone open.

The coverage ledger records **form ID · reference section · exact English sentence · existing / partial / missing / needs design · game chapter and scene · test or replay · expected observation · result**. Each accepted spelling maps to its source span and compiler form. Compiler instrumentation identifies the branch taken, and runtime traces establish execution.

| Example ledger entry | Game use | Evidence required |
|---|---|---|
| §9.5 named kept property | The party lead’s HP gauge follows its current HP | Switch leads, take damage, then reload. The same gauge follows the right Pokémon each time. |
| §§7.6, 13.15 human choice reply | The companion’s starter practice asks for a typed choice | An invalid answer prompts again. Each valid choice resolves to its declared type. The game itself uses Oak’s original selection and confirmation inputs. |
| §12.7 strand conflict | Two battle effects try to write the same HP value | The compiler refuses the conflicting program before execution. Disjoint party animations compile and finish in the documented order. |
| §7.8 model image input | Oak’s Field Lab asks the judge about a frame drawn by the game | Generate the frame from the scene’s drawing commands, pass it through the documented image form, and check the recorded request and reply. |

The companion can interpret approachable Pokémon through temperament and synthesized cries. In-game encounters keep the reference animations and sounds. ## 6. Pixels, sound, DOM and model delivery

The [browser microarchitecture](EnglishScript%20-%20Browser%20microarchitecture.md) assigns the cartridge to one Pyodide simulation worker, the real canvas and audio device to the browser window, and pure battle calculations to separate workers. It defines how a button edge becomes a cartridge tick and a displayed pixel, how a suspended model call resumes, and how to measure parallel work. Review these boundaries alongside the proposed language syntax.

**Canvas in the DOM binding.** Extend `Use the page library.` with a `canvas` kind. In EnglishScript, the game declares its screen with the proposed sentence `There is a canvas called Game Screen whose width is 160 and whose height is 144.` The existing page binding creates the native `<canvas>` in its mount or assigned panel, sets the intrinsic dimensions once, and retains the node and its 2D context across turns, chat updates and resizes of the window. Hiding or reparenting the screen follows the page library’s existing element lifecycle. On removal or program shutdown, release listeners and presentation callbacks. Give the screen a focus target and accessible name.

**Drawing and presentation.** EnglishScript procedures draw menus, glyphs, maps and Pokémon into the four-shade frame through batched integer drawing operations. Match palette changes, sprite transparency, layering and scroll offsets before presentation. The browser binding expands the completed frame through a fixed opaque sRGB palette into a reusable `ImageData` and presents it with `putImageData`. Set integer CSS display dimensions and `image-rendering: pixelated` for enlargement. The backing surface stays at 160×144 across window sizes and device pixel ratios. [HTML Canvas 2D pixel operations](https://html.spec.whatwg.org/multipage/canvas.html#pixel-manipulation)

**Canvas acceptance test.** Instantiate the screen from an `.english` chapter through the normal page binding. In a real browser, assert that the bound node is an `HTMLCanvasElement` and keeps its identity while a chat field updates. In parity runs, read the actual 160×144 canvas with `getImageData`, map its RGBA values back to the four reference shades, reject off-palette pixels and compare every position on every game frame. Exercise the same procedural inputs in the headless page backend. Verify integer enlargement independently and measure live frame pacing with pixel readback disabled.

**Audio.** Express the reference notes, rests, envelopes, pulse duty, wave channel, noise, pitch changes and cries as sound programs. Run them against the game clock and schedule playback against the audio device clock. Compare the sequence and timing of audio channel events against the reference for the title, lab, forest, battles, menus and badge. Use a fixed offline synthesizer and sample rate when comparing waveforms. Timed input and audio cues matter even on a frame where the picture stands still.

**Interaction.** Map game controls to Game Boy button edges. Provide DOM accessibility equivalents outside the native surface. Free chat uses a separate companion input and cannot leak keystrokes into game controls. In a live nonmodal session, the game clock continues and the recording includes the intervening idle time. If a player explicitly pauses to chat, freeze the game at a known tick, including its timer and RNG, and resume from that tick. In both cases compare against a reference run with the same game-clock input history. Exercise movement and audio while a nonmodal request is pending. Keep provider keys server-side. Discard replies addressed to a closed conversation, former speaker or replaced save.

**Three systems.** System 0 implements Red’s game rules. Jev and GPT‑6 Luna can play the trainer’s side of the original game by choosing legal controller inputs. For each policy, send that exact button recording to both implementations. The policy can change the decision to switch or attack. Once that decision is made, the original opponent AI, damage, dialogue and reward must agree. Benchmark rules alone, rules + Jev, rules + Luna, Jev then Luna, and Luna then Jev under equal visible information. Score model latency, cost, illegal suggestions, prediction calibration and battle outcomes separately from cartridge parity. Free NPC conversation uses all three systems in the companion. The offline fallback is persona-specific.

### Resume a browser session

Use the browser’s Cache Storage API for best-effort session recovery. After a settled map transition, battle turn, completed NPC exchange, or periodic safe checkpoint, the World and People books supply one consistent snapshot. The page binding writes it asynchronously. A refresh or browser restart offers **Resume session** in the companion when a compatible checkpoint exists. The cartridge title screen and its original **Continue** command still follow the player’s explicit in-game save. The existing page-library `Remember` operation remains available for small preferences. [Page-library storage](https://github.com/monstercameron/EnglishScript/blob/acf28a2/docs/PAGE.md#remembering) · [Browser storage and eviction](https://storage.spec.whatwg.org/#storage-buckets)

Store the campaign state, cartridge tick, timer and RNG state, plus committed NPC memories and journal position together. Identify the save slot, campaign generation, checkpoint sequence, content version and schema. Keep a current and previous completed checkpoint per slot. Serialize writes for a slot so an older completion cannot overwrite a newer one, including when two tabs are open. Resume from the saved game tick and create a fresh conversation generation. Provider credentials and pending model requests stay outside the snapshot.

If the browser evicts the cache, denies access, or runs out of space, play continues and the companion reports whether recovery is available. A corrupt or incompatible checkpoint falls back to the previous compatible entry when possible. **Forget session** clears only that slot’s recovery data. Use an explicit save export for a copy the player can keep outside browser storage.

**Acceptance test.** Deliver Oak’s parcel and finish a conversation with the clerk, then reload without making a cartridge save. Resuming must reproduce the same world, inventory and NPC memory without granting a second Pokédex. Feed the same subsequent button inputs to the resumed and uninterrupted sessions and compare game state and canvas frames. Also cover browser restart, interrupted writes, two tabs, cache eviction, quota refusal, an incompatible version, and clearing recovery while a Luna reply is pending.

**Performance.** Drive the game with the DMG clock and measure presentation separately on a recorded 60 Hz browser/device combination. During a two-minute forest walk and a two-minute battle/chat workload, report simulation speed versus cartridge time, game frames generated, capture mismatches, dropped presentations, p50/p95/p99 display intervals, input-to-paint latency and audio underruns. Repeating a game frame to accommodate monitor refresh is expected. Advancing the simulation early to fill a display refresh is a parity failure. Initial presentation targets are at least 99% of scheduled presentations on time, p95 input-to-paint under 50 ms and zero observed audio underruns or stale model commits. Inject a five-second model delay and repeat.

**Evidence and reporting.** Pin the compiler, game revisions, emulator settings, controls, clock phase, initial save, listener configuration and recorded model results.
