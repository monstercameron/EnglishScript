# Boulder Badge · Browser microarchitecture

**Review decision.** Give the cartridge one clock, one long-lived EnglishScript world and one writer. Run it in a dedicated browser worker. Keep the real canvas, input and audio device in the window. Add separate workers for pure EnglishScript calculations when the Field Lab requests them. This lets a player keep walking while Oak thinks and lets us test whether two battle calculations actually run in parallel.

## What the current build allows

The playground at `acf28a2` loads **Pyodide 0.26.4** in the window. Startup is asynchronous. Once loaded, the playground calls Python synchronously. An interactive question returns control to the page, which runs the program again from the beginning with the accumulated answers. A game needs to resume the exact pending call without repeating a sound, a purchase or an encounter. The existing page backend looks for `js.document` and selects its in-memory `Paper` backend inside a worker. The to-do demo also accesses the window interpreter directly. Keep these entry points working while bringing up a separate game runner. [Playground engine](https://github.com/monstercameron/EnglishScript/blob/acf28a2/docs/play/engine.js) · [Page backend](https://github.com/monstercameron/EnglishScript/blob/acf28a2/englishscript/libraries/page.py) · [To-do integration](https://github.com/monstercameron/EnglishScript/blob/acf28a2/docs/todo.html)

| Pyodide 0.26.4 constraint | Design consequence |
|---|---|
| `runPythonAsync` supports top-level await. Python runs on its owning event loop until it yields. By default `WebLoop.run_until_complete` schedules work and returns a future. | Represent waits explicitly and return control to the browser between bounded slices. A synchronous Python loop can starve its worker’s input and completions. An async wrapper alone cannot fix it. [JavaScript API](https://pyodide.org/en/0.26.4/usage/api/js-api.html#pyodide.runPythonAsync) · [Tagged WebLoop implementation](https://github.com/pyodide/pyodide/blob/0.26.4/src/py/pyodide/webloop.py) |
| Python’s `threading` and `multiprocessing` modules can import but cannot provide the corresponding native execution on this build. Each Web Worker has its own interpreter and globals. | Each worker that evaluates Python loads the pinned runtime and required books. Pass typed values across workers. Budget startup time and memory per interpreter. [Compatibility](https://pyodide.org/en/0.26.4/usage/wasm-constraints.html#included-but-not-working-modules) · [Worker caveats](https://pyodide.org/en/0.26.4/usage/webworker.html#caveats) |
| The optional `run_sync` path depends on WebAssembly JavaScript Promise Integration and a suitable async entry point. A Pyodide interrupt requires worker execution, a shared interrupt buffer and the appropriate deployment headers. Some code must explicitly check for signals. | The baseline uses ordinary worker messages, transferable buffers and cooperative cancellation. Test with cross-origin isolation disabled. Treat shared-buffer interrupts as an optional capability and version-test them separately. [Synchronous waiting API](https://pyodide.org/en/0.26.4/usage/api/python-api/ffi.html#pyodide.ffi.run_sync) · [Interrupts](https://pyodide.org/en/0.26.4/usage/keyboard-interrupts.html) |

**Observed in a browser.** A clean headless Edge 157.0.4341.60 worker loaded the playground’s shipped compiler archive and Pyodide 0.26.4 (Python 3.12.1). A scheduled Python callback had not fired immediately and had fired after `await asyncio.sleep(0)`. Starting a Python thread raised `RuntimeError: can't start new thread`. Constructing the shipped page backend selected `Paper`. These observations establish the baseline for the first browser gate.

## Ownership and interfaces

| Owner | State and work | Boundary |
|---|---|---|
| Window and page library | The actual 160×144 HTML canvas, companion DOM, focus, accessibility, controller input, audio device and presentation clock | The worker-side page backend sends stable element IDs and batches of changes. The window applies them and returns typed events. A game startup handshake must confirm a real canvas. Remove listeners and outstanding subscriptions when an owner closes. |
| Simulation worker, System 0 | The compiled books, one live `World`, cartridge clock, divider, RNG, input latch, maps, party, actors, battle state, strand scheduler and committed NPC memories | Accept sequenced input and completions. Publish frames, sound events, effects and settled checkpoints. The World, Battle, Pictures and Music books determine the content. Only this worker commits it. |
| Model and storage adapters | Asynchronous transport to server-side Jev (System 1) and GPT-6 Luna (System 2), request cancellation, preference storage and Cache Storage | Send a snapshot and typed request. Return a typed reply or error. Keep provider credentials on the server. Preload small synchronous page preferences into the worker and mirror writes through the host. Campaign recovery uses versioned, acknowledged checkpoints. |
| Compute workers | Pure, compiler-approved worked-out verbs for independent calculations such as comparing damage across a team | Dispatch a registered verb ID, matching program revision, typed immutable arguments and job ID. Return a typed value or error. Each worker initializes the needed code locally. The owner joins results in declared order. |

**Compiler and scheduler.** Extend the existing compiler at the block and verb boundaries. For code that may suspend, including indirect calls and reactions, emit resumable steps with a source location. Keep the instruction position, arguments, locals, pronouns, loop position, pending join and active error/cleanup frames. A suspended `Try` carries its strand’s change journal. The scheduler delivers a resolved effect once at the next eligible scheduling boundary. Bound long loops and expensive library primitives so the worker can service host messages. A host yield can enqueue inputs without switching language strands or exposing a half-settled mutation. The existing synchronous CLI remains a driver of the same language semantics. ## One input, from button to pixel

1. The window timestamps a press or release against a shared session epoch and gives it a sequence number. The simulation maps it to a cartridge tick using integer clock units. A late edge first becomes visible at the next eligible input sample. Record its original timestamp, applied tick and sequence for replay. Preserve both edges of a short tap. On focus loss, enqueue releases for held buttons and require fresh presses after focus returns.
2. In live play, elapsed monotonic time sets the latest cartridge tick the worker may simulate. Within that budget advance to each due input, timer or game event in reference order. An offline replay takes its budget from the trace. Match input sampling, divider reads, RNG consumption, movement and battle decisions against the pinned reference, including equal-tick ordering. Pausing a hidden tab freezes the cartridge clock. On return, rebase the wall-clock epoch and apply pending releases before fresh inputs.
3. At each completed game frame, the Pictures book finishes one 23,040-byte indexed surface. Copy it once from a short-lived Python buffer view into a pooled, transferable JavaScript buffer. Release the view and send the standalone buffer tagged with its frame number and game tick. The window expands the four shades into reusable RGBA storage and paints the existing canvas. Recycle the transferred buffer by acknowledgement. In live play present the newest completed frame and count every skipped presentation. In parity mode wait for canvas readback acknowledgement **on every frame** before reusing the buffer or advancing the harness. [Pyodide buffer API](https://pyodide.org/en/0.26.4/usage/api/js-api.html#pyodide.ffi.PyBuffer.getBuffer)
4. The Music book emits timestamped channel changes. The host batches and schedules them against the audio device clock with measured look-ahead. Resynchronize on pause, resume and device suspension. Keep Python, model calls and storage writes out of the device callback. The harness compares cartridge-tick audio events even when the browser device is muted.

## Backpressure, cancellation and recovery

A worker reports a failed call with a structured diagnostic carrying its identifier, English problem kind when catchable, severity and original chapter span. Preserve the originating call site through a suspended request. The receiving runner uses the recovery disposition to resume the handler or end the run. The companion can then explain the consequence to the player. The [standard library and diagnostics plan](EnglishScript%20-%20Standard%20library%20and%20diagnostics.md) defines the formatting and round-trip tests.

Tag every request with session generation, owner generation and a monotonic request ID. Match each completion to its live subscriber before delivery. Closing a chat invalidates that subscription immediately. An abort can release transport work. A duplicate or delayed completion cannot publish dialogue, change a later conversation, or submit controller input. A model acting as the player can submit only a validated controller action through the same recorded input path.

Bound each queue according to what it carries. Input and audio events retain their sequence and require acknowledgements. If an acknowledgement stalls, pause at the last consistent boundary and report the overrun. Keep at most one pending live presentation beyond the frame being painted. Limit compute jobs in flight and suspend a submitting strand when its queue fills. Warm one compute worker on demand. Start a second for the parallelism benchmark and measure the extra cost. On a device that cannot allocate the pool, report the degraded mode and run eligible work in bounded serial slices. A serial run earns no parallel-worker coverage.

If a pure worker stops answering, invalidate the job, terminate that worker after a deadline and replace it on demand. Its inputs can be retried under a fresh ID. Recover a failed simulation worker from the latest settled, acknowledged checkpoint and explicitly identify its tick. A checkpoint contains the cartridge, committed companion state and input journal position. Defer it while a campaign action is in flight. Pending optional requests end with the old generation. Follow the [session recovery rules](EnglishScript%20-%20The%20Boulder%20Badge%20benchmark%20plan.md#resume-a-browser-session) for eviction, two tabs and interrupted writes.

## Build gates

| Order | Proof required before moving on |
|---|---|
| 1. Boot and reach the physical canvas | Load the pinned runtime in a worker and mount one canvas through an EnglishScript chapter. A DOM button must cause one worker-side state change and one observable pixel change. Confirm that choosing `Paper` fails this browser test. Smoke-test the existing playground question flow, to-do page and headless backend. |
| 2. Suspend and resume through a real scene | During a long EnglishScript loop, return to the browser task queue between slices and acknowledge a real window-to-worker message before the loop finishes. Delay a model reply five seconds while walking and playing audio. Observe a window heartbeat **and** continuing simulation ticks. Verify nested waits and a suspended `Try` resume once, without repeating prior output. Close Oak’s chat, open the rival’s, deliver the old response and assert zero stale commits. |
| 3. Verify worker isolation and measure speedup | Run two pure damage calculations on distinct workers. Require a start rendezvous, reverse their finish order and compare joined results and campaign state hashes. Separately repeat the same fixed CPU workload serially, with one worker and with two warm workers. Report timings, variation and speedup. A rendezvous proves independent execution contexts. If timing is inconclusive, mark CPU speedup unproven. Record startup, payload sizes, queue wait and memory where measurable. Exercise unavailable workers, timeout and cancellation without shared memory. |
| 4. Measure parity and pacing separately | Replay the same input on the reference and browser. Require identical frame counts, every canvas shade, compared state and audio event timing. In separate two-minute live runs on a recorded 60 Hz configuration, target at least 99% on-time presentations, p95 input-to-paint below 50 ms and zero audio underruns with a model request pending. Record missed game ticks, frame drops and queue high-water marks. |
| 5. Recover and requalify | Reload at a checkpoint with a reply in flight, repeat after cache eviction, and hide/show the tab during a held button. Compare subsequent inputs and frames with the corresponding uninterrupted or paused replay. Run the capability and parity gates again when changing Pyodide or browser versions. |

The first implementation slice is **one button, one game tick, one real canvas pixel and one suspended request**. This tests the proposed thread and compiler boundaries before the opening sequence depends on them. [Full benchmark plan](EnglishScript%20-%20The%20Boulder%20Badge%20benchmark%20plan.md)
